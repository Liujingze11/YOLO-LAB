# i18n Multi-Language Support

## Overview
Add runtime-switchable multi-language support (zh/en/fr/es) to GUI and subprocess terminal output.

## Languages
- Chinese (zh), English (en), French (fr), Spanish (es)

## Architecture

### File Structure
```
gui/locales/{zh,en,fr,es}.json    # Translation files (~100 keys each)
gui/gui/i18n.py                    # Translation manager
```

### Translation Manager (`i18n.py`)
- `load_locale(lang)` — load JSON into memory
- `tr(key)` — return translated string for current language
- `apply_language(root)` — recursive walk, update widgets by `i18nKey` property
- `language_changed` Signal

### Widget Updates
Each widget gets `setProperty("i18nKey", "module.component.name")`.
`apply_language()` reads the key, looks up translation, calls appropriate setter:
- QLabel/QPushButton/QCheckBox/QRadioButton → `setText()`
- QTabWidget → `setTabText(i, text)`
- QComboBox → `setItemText(i, text)` per item

### Subprocess Integration
train_engine.py / infer_engine.py accept `--lang zh` argument, load same JSON file, translate `print()` strings.

### Language Switcher
QComboBox next to dark mode button in corner widget area.

## Key Design Decisions
- JSON key format: dot-separated hierarchy (`train.btn.start`)
- Translation files fully loaded at startup; switching is instant
- Same JSON files shared between GUI and CLI subprocesses
- Follows existing `themeClass` pattern (widget property + recursive walk)
